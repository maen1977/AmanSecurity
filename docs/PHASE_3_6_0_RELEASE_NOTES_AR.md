# AmanSecurity 3.6.0 — ملاحظات التطوير والإطلاق

**الحزمة:** `com.aman.security`  
**versionCode:** `40`  
**النموذج:** حماية محلية أولًا، بلا سحابة مدفوعة أو رفع لمحتوى المستخدم

## ملخص التطوير

يركّز هذا الإصدار على جعل حالة الحماية قابلة للتحقق بدل الاكتفاء بعبارة عامة مثل «Protection مفعّلة». أضيف مؤشر جاهزية محلي داخل مركز الحماية، ويعتمد على إشارات حقيقية من قاعدة التهديدات، خدمة الحماية، مراقبة تثبيت التطبيقات والتنزيلات، اختبار حماية الويب، فحص التسلل، وفحص مؤشرات تسريب البيانات.

لا يعلن التطبيق الحالة القوية قبل اكتمال الاختبارات الأساسية. إذا كانت طبقة غير مفعّلة أو لم تُختبر، تظهر حالة تحتاج إلى انتباه بدل إعطاء المستخدم شعورًا زائفًا بأن كل المخاطر مغطاة.

## ما تم الحفاظ عليه

| المجال | القرار في 3.6.0 |
|---|---|
| الخصوصية | فحص الملفات والتطبيقات والرسائل والروابط محليًا؛ لا رفع لمحتوى المستخدم |
| التكلفة | لا خدمة سحابية مدفوعة ولا حساب سحابي مطلوب للحماية المحلية |
| التحديثات | تحديث قاعدة التهديدات الموقّع دوريًا تقريبًا كل 24 ساعة، مع تحديث يدوي فوري |
| الأداء | فحوص محدودة، ذاكرة cache، WorkManager، وفحص قائم على الأحداث بدل polling كثيف |
| التوافق | `minSdk 26` و`targetSdk 36` |
| الصلاحيات | لم تُضف صلاحيات SMS أو Call Log أو Accessibility جديدة |
| التخزين | فحص SAF للمجلدات، فحص التنزيلات، وفحص APK/ZIP بحدود زمنية وحجمية |

## مؤشر الجاهزية

مؤشر الجاهزية هو **مؤشر تغطية واختبار** وليس نسبة ضمان للحماية. من أمثلته:

- سلامة نسخة قاعدة التهديدات المحلية.
- نبض خدمة الحماية المستمرة.
- تفعيل مراقبة التطبيقات والتنزيلات.
- نجاح اختبار Web Shield أو وجود دليل اعتراض حديث.
- وجود فحص تسلل حديث.
- وجود فحص مؤشرات تسريب بيانات حديث.

لن يحوّل المؤشر نتيجة فحص محلية إلى وعد بأن التطبيق يكتشف كل برمجية ضارة أو يمنع كل اختراق.

## الاختبار الآمن المضمّن

تحتوي قاعدة التهديدات على **هاش EICAR القياسي ذي 68 بايتًا فقط** مع تصنيف `TEST_SIGNATURE` وبيانات وصفية `EICAR`. لا يحتوي المستودع أو APK على عينة قابلة للتنفيذ. يمكن استخدام ملف EICAR الرسمي الآمن من مصدره لاختبار الفحص، أو استخدام canary المحلي المرفق بتقرير الاختبار.

معيار النجاح هو أن يظهر الفحص نتيجة اختبار واضحة مثل `TEST_SIGNATURE` أو `EICAR`، لا أن يُعامل الملف كتهديد حقيقي أو يُحذف تلقائيًا.

## نتائج التحقق المحلي

نجحت بوابات الجودة المحلية، ومنها:

- `PROTECTION_READINESS_GATE_OK`
- `STORAGE_IMPROVEMENTS_GATE_OK`
- `WEB_SHIELD_VERIFICATION_3_4_OK`
- `REALTIME_ANTIVIRUS_GATE_OK`
- `DATA_EXFILTRATION_GUARD_3_3_OK`
- `ANDROID_API_COMPAT_GATE_OK`
- `ANDROID_STRING_FORMAT_GATE_OK`
- `PLAY_RELEASE_GATE_OK`

كما اجتاز benchmark الداخلي الآمن عينة `15` حالة ضارة اصطناعية و`15` حالة سليمة بنتيجة `TP=15`, `TN=15`, `FP=0`, `FN=0`، وبمتوسط زمن فحص محلي يقارب `16.83 ms` ومتوسط ذاكرة ذروة يقارب `23.37 MB`. هذه نتيجة لاختبار داخلي محدود وليست تصنيفًا مستقلًا لمضاد فيروسات تجاري.

## الحدود التي يجب ذكرها للمستخدم

AmanSecurity لا يفك تشفير HTTPS العام ولا يقرأ محتوى الصفحات المشفّرة، ولا يملك صلاحية منع كل سلوك داخل تطبيق آخر، ولا يستطيع ضمان اكتشاف كل spyware أو banking trojan أو zero-day. حماية التطبيقات البنكية تعتمد على مؤشرات محلية وتحذيرات وإعدادات يراجعها المستخدم، وليست بديلًا عن حماية البنك أو Android.

كذلك لا يمكن لبوابات الكود وحدها إثبات أن الخدمة تعمل على كل هاتف. يجب اختبار APK على أجهزة Android فعلية، مع تجربة إعادة التشغيل، رفض الإشعارات، وضع توفير البطارية، تعطيل VPN، تثبيت APK، تنزيل ملف، فحص مجلد، ومشاركة رسالة أو رابط.

## قبل النشر

يجب على مالك المستودع تنفيذ اختبار داخلي على عدة أجهزة، توقيع AAB بمفتاح Google Play خارج المحادثة، مراجعة سياسة الخصوصية، استكمال Data Safety وAll files access وpackage visibility، ثم رفع AAB إلى Internal Testing قبل الإنتاج. لا يقوم workflow الحالي بالنشر التلقائي إلى Google Play.
